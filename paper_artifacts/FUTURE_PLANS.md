**Дата фиксации:** 14 октября 2026

## 1. Концепция исследования и академический пробел (Research Gap)

### Тезис
Современная литература 2024–2026 гг. демонстрирует взрывной рост 1.58-битных архитектур, однако все публикации (Microsoft, Meta, TII) страдают от двух фундаментальных ограничений:
1. **Одношаговые синтетические бенчмарки:** Тестирование ведется на перплексии (WikiText-2) и стандартных задачах с изолированным контекстом (MMLU, GSM8K, IFEval). Поведение тернарных сетей в агентных циклах (вызов внешних инструментов, удержание истории диалога, устойчивость к галлюцинациям синтаксиса JSON) не исследовано.
2. **Теоретический расчет энергии вместо сквозного замера:** Официальные заявления об энергоэффективности (например, 0.028 Дж/токен у BitNet 2B4T против 0.186–0.649 Дж у Gemma-3/Qwen2.5) получены по теоретической формуле арифметических операций (AOE, Mark Horowitz 2014). Они игнорируют реальное энергопотребление DRAM, задержки шины памяти, накладные расходы рантайма и необходимость повторных вызовов (retry loops) из-за ошибок парсинга.

## 2. Экспериментальный план (Future Experiments)

### Эксперимент 1. Метрика «Energy-to-Success» (Дж на решенную агентную задачу)
* **Цель:** Доказать или опровергнуть гипотезу о том, что низкое энергопотребление на токен у 1.58-битных моделей компенсирует возможное падение синтаксической точности в многошаговых агентных циклах.
* **Формула замера:**
  $$\text{Energy-to-Success} = \sum_{k=1}^{K} \int_{t_{\text{start}}}^{t_{\text{end}}} P(t)\,dt \quad [\text{Дж}]$$
  где $P(t)$ — реальная суммарная мощность процессора/памяти (по данным Intel RAPL / AMD μProf / NVIDIA NVML), а $K$ — число шагов до валидного ответа.
* **Аппаратные платформы:**
  * CPU Edge: Intel Core i7 / AMD Ryzen (AVX2/FMA, через `bitnet.cpp` с I2_S ядрами).
  * GPU: NVIDIA RTX (через нативный PyTorch и кастомные CUDA ядра).

### Эксперимент 2. Масштабирование агентной дистилляции (Agent BitDistill)
* **Цель:** Перенос структурных агентных навыков (Tool Calling, Coreference Resolution, JSON Strict Schema) из сильного учителя (Qwen 2.5 Coder 7B / DeepSeek) в BitNet 2B.
* **Масштаб датасета:** Расширение с пилотных 25 диалогов до 1 000+ валидированных многошаговых сценариев (ToolBench-lite, Berkeley Function Calling Leaderboard subset).
* **Архитектурный пайплайн:**
  * Дообучение адаптеров LoRA ($r \ge 16$, $\alpha \ge 32$) с градиентным клиппингом и FP32-накопителем.
  * Исследование constrained grammar decoding (GBNF / regex-маскирование) в рантайме для 100% гарантии синтаксической валидности JSON без подгонки гиперпараметров sampling.

### Эксперимент 3. Мультиагентные гетерогенные топологии (Multi-Agent Swarm)
* **Сценарий:** Сравнение трех архитектур оркестрации в задаче совместного решения исследовательского тикета:
  1. *Dense Homogeneous:* Оркестратор и воркеры на базе Qwen 1.5B (FP16 / INT4).
  2. *Ternary Homogeneous:* Оркестратор и воркеры на базе BitNet 2B (`bitnet.cpp` I2_S).
  3. *Hybrid Orchestrator-Workers:* Dense-оркестратор (высокая способность к рассуждению) + пул параллельных тернарных агентов (CPU resident, микро-потребление RAM 0.4–1.1 ГБ) для массового поиска, парсинга и вызова тулов.
* **Ключевой замер:** Энергопотребление и задержка при одновременной работе 4–8 агентов в RAM/L3-кэше без свопинга.

## 4. Ожидаемые научные результаты публикации

1. Первая в литературе сравнительная характеристика метрик **Dual Recall (Trigger Recall vs Execution Recall)** для 1.58-битных моделей.
2. Эмпирическое опровержение или подтверждение теоретических энергооценок Microsoft на реальном агентном цикле (Intel RAPL).
3. Практические рекомендации по стабилизации тернарного инференса (penalty vs grammar constraints) без искажения стохастичности через искусственную подгонку температуры.

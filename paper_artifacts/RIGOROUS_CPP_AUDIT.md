# Выверенный покейсовый аудит C++ рантайма (Без завышений)

## Обновленные правила классификации:
1. **S1 (Текстовая попытка вызова)**: фиксирует наличие в сгенерированном тексте синтаксического JSON-конверта или функционального вызова, а не факт нативного вызова инструмента в рантайме. Постобработка JSON не является реальным исполнением. Эхо списка инструментов промпта и плейсхолдеров (`'tool': 'name'`) исключены.
2. **S2 (Схема конверта валидна)**: зарегистрированное имя инструмента (из 5 разрешенных), словарь `parameters`/`arguments`, отсутствие неизвестных параметров (`extra_fields = False`) и соответствие типов.
3. **S3 (Статическая эвристическая проверка аргументов)**: проверка наличия ожидаемых сущностей и синтаксический разбор `ast.parse` для Python без выполнения кода и без анализа графа алгоритма.
4. **S4 (Выполнение в изолированной среде)**:
   - SQL: запуск в SQLite :memory: под authorizer (только SELECT к целевой таблице) и progress_handler (прерывание после ~500 000 инструкций виртуальной машины SQLite: 50 000 срабатываний с шагом 10 инструкций; не является секундным тайм-аутом).
   - Файлы: чтение локальных дисковых фикстур стенда (test_fixtures).
   - Python: **Не исполнялось (нет изоляции ОС)**. Произвольный запуск отключен по соображениям безопасности.
   - Погода / Поиск: **N/A (Внешний API)**. Внешние сервисы не эмулируются.
5. **S5 (Результат верен на фикстуре)**:
   - SQL: проверка формы [(2,)] для кейса 11; совпадение упорядоченных сумм [950, 800, 500, 300, 200] для кейса 12 на данной фикстуре (наличие конструкции ORDER BY DESC в AST отдельно не проверяется).
   - Файлы: проверка маркеров в прочитанном файле фикстуры.
6. **Отсутствие синтаксиса вызова (Non-Tool)**: оценивается на 5 негативных кейсах (штраф за синтаксис инструмента, включая фиктивный `{'tool': 'none'}`).
